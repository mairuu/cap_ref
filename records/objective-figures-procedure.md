## 0. ก่อนเริ่ม: ย้ายผลเก่าออก

ใช้พิกัดจากไฟล์ผลลัพธ์ร่วมกันได้เฉพาะเมื่อมาจาก `make slam` ครั้งเดียวกันเท่านั้น
เพราะทุกครั้งที่รัน `make slam` กรอบพิกัด map จะถูกสร้างใหม่ ดังนั้นให้ย้ายไฟล์เก่าไปเก็บไว้ก่อน
**ไม่ต้องลบ** เพราะไฟล์ของวันที่ 22 ก.ย. เป็นข้อมูลจริงชุดเดียวที่มีอยู่

```bash
mkdir -p ~/maps/archive-0922
mv ~/maps/slam_accuracy.jsonl ~/maps/resource_session.jsonl ~/maps/archive-0922/
# ถ้ามี tape_session.jsonl ก็ย้ายด้วย (ตอนนี้ยังไม่มีไฟล์นี้)
```

`cd ~/cap_ws && colcon build --packages-select my_bot` หนึ่งครั้ง เพื่อติดตั้ง
`resource_report.py` และ `landmark_tape_measure.py` เวอร์ชันใหม่ ซึ่งบันทึกข้อมูลรายจุดสำหรับวาดกราฟ

## 1. เตรียมพื้นที่ (ก่อนเปิดระบบ)

ต้องเตรียมพื้นที่ **ไม่น้อยกว่า 5×5 ม.** ตามเกณฑ์ข้อ 1 โดยให้จุดอ้างอิงกระจายเป็นสองมิติ
รอบวันที่ 22 ก.ย. วางจุดไว้บนเส้นเดียวยาว 4.2 ม. จึงยังอ้างว่าเป็นพื้นที่ 5×5 ม. ไม่ได้

1. ติดเทปเป็นรูปกากบาทที่พื้นหนึ่งจุด เรียกว่า **HOME** จอดหุ่นยนต์บนจุดนี้โดยหันหน้า **ขนานกับผนัง**
2. ติดกากบาทอีก **3–4 จุด** ให้ห่างจาก HOME ไม่น้อยกว่า 5 ม. ในแกน x และไม่น้อยกว่า 3–5 ม. ในแกน y
3. ใช้ตลับเมตรวัดพิกัดของทุกจุดเทียบกับ HOME
   - **x** คือระยะตามทิศที่หุ่นยนต์หันหน้า
   - **y** คือระยะไปทาง **ซ้าย** ของหุ่นยนต์ (ถ้าอยู่ทางขวาให้ใส่ค่าติดลบ)
4. วางวัตถุทดสอบ เช่น เก้าอี้ แล้ววัดพิกัด x, y ของจุดกึ่งกลางวัตถุด้วยวิธีเดียวกัน
5. **จดพิกัดทั้งหมดลงกระดาษก่อนเริ่มทดสอบ** ตัวอย่างเช่น

| จุด | x (ม.) | y (ม.) |
|---|---|---|
| HOME | 0 | 0 |
| MARK_B | 5.00 | 0.00 |
| MARK_C | 5.00 | 3.50 |
| MARK_D | 0.00 | 3.50 |
| chair | ___ | ___ |

## 2. เปิดระบบ (หุ่นยนต์ต้องจอดอยู่บน HOME)

```bash
cd ~/cap_ws && make ports     # ต้องเห็นทั้ง /dev/esp32 และ /dev/ydlidar
make real        # T1

make nav         # T3
make yolo        # T4
make semantic    # T5
```

เทอร์มินัลที่รันคำสั่ง `ros2 run` ทุกหน้าต่างต้องรันบรรทัดนี้ก่อน:
```bash
source /opt/ros/humble/setup.bash && source ~/cap_ws/install/setup.bash
```

## 3. เกณฑ์ข้อ 5: ทรัพยากร (วัดสามช่วงเพื่อเปรียบเทียบกัน)

กราฟ (ข) ของรูปนี้เปรียบเทียบสามสถานการณ์ ส่วนกราฟ (ก) คือกราฟตามเวลาของช่วงที่วัดล่าสุด
ให้วัดตามลำดับนี้ เพื่อให้ช่วงระบบเต็มถูกวัดเป็นช่วงสุดท้าย

```bash
# ช่วง 1: ก่อนเปิดระบบในข้อ 2 (บอร์ดว่าง) วัด 2 นาที
ros2 run my_bot resource_report.py --seconds 120 --label "idle"

# ช่วง 2: หลังรัน make real + make slam แต่ยังไม่รัน yolo, semantic
ros2 run my_bot resource_report.py --seconds 180 --label "real+slam"

# ช่วง 3: ระบบเต็ม ให้รันคำสั่งนี้ "ก่อน" เริ่มขับในข้อ 4 แล้วปล่อยไว้ตลอดรอบ
ros2 run my_bot resource_report.py --seconds 1800 --label "full stack, driving"
```
ถ้าขับเสร็จก่อนครบเวลา ให้กด Ctrl-C สคริปต์จะสรุปผลและบันทึกข้อมูลเท่าที่เก็บได้ไว้ครบ

## 4. เกณฑ์ข้อ 1: SLAM (ขับ 3 รอบ และหยุดที่ทุกจุด)

```bash
cd ~/cap_ws && make teleop-nav SPEED=0.10      # ขับที่ 0.10 m/s เท่านั้น ถ้าเร็วกว่านี้ภาพสแกนจะเบี้ยว
```
เมื่อจอดนิ่งบนกากบาทแต่ละจุดแล้ว ให้รันคำสั่งหนึ่งบรรทัดในเทอร์มินัลอื่น
สคริปต์จะเฉลี่ยค่า 5 วินาที ระหว่างนั้น **ห้ามขยับหุ่นยนต์**

```bash
ros2 run my_bot slam_accuracy_check.py mark HOME   --truth 0 0
ros2 run my_bot slam_accuracy_check.py mark MARK_B --truth 5.00 0.00
ros2 run my_bot slam_accuracy_check.py mark MARK_C --truth 5.00 3.50
ros2 run my_bot slam_accuracy_check.py mark MARK_D --truth 0.00 3.50
```
ทำซ้ำให้ครบ **3 รอบ** โดยจบทุกรอบที่ HOME
แต่ละรอบจะกลายเป็นจุดหนึ่งจุดในกราฟ (ข) และทั้งสามรอบรวมกันคือค่าการวัดซ้ำ (repeatability)

- ถ้าสคริปต์แสดง `Sample NOT recorded` แปลว่าหุ่นยนต์ยังขยับอยู่ ให้รอจนนิ่งแล้วรันใหม่
- ห้ามยกหรือหมุนหุ่นยนต์ด้วยมือระหว่างการทดสอบ

## 5. เกณฑ์ข้อ 4: ตำแหน่งวัตถุ (4 มุมมอง)

ขับไปจอดห่างจากวัตถุประมาณ **1.6 ม.** จากแต่ละด้าน แล้ววัดด้านละ 30 วินาที
ถ้าจอดใกล้กว่านี้ ช่วงสแกนจะครอบทั้งวัตถุและพื้นหลังจนระบบปฏิเสธค่า

```bash
ros2 run my_bot landmark_tape_measure.py chair --truth X Y --pass-label front
ros2 run my_bot landmark_tape_measure.py chair --truth X Y --pass-label right
ros2 run my_bot landmark_tape_measure.py chair --truth X Y --pass-label back
ros2 run my_bot landmark_tape_measure.py chair --truth X Y --pass-label left
```
ใส่ค่า `X Y` จากข้อ 1.4 และต้องใช้ค่าเดียวกันทุกครั้ง ถ้าย้ายเก้าอี้ต้องเริ่มชุดใหม่

## 7. วาดกราฟ

```bash
python3 ~/cap_ws/src/my_bot/scripts/plot_objectives.py all --out ~/cap_ref/figures
#   --lang en   ถ้าต้องการป้ายกำกับภาษาอังกฤษ
#   --window "full stack"   เลือกช่วงที่จะแสดงเป็นกราฟตามเวลา (ค่าเริ่มต้นคือช่วงล่าสุด)
```

สคริปต์จะพิมพ์ตัวเลขที่ใช้วาดกราฟออกมาด้วย ให้คัดลอกค่าเหล่านี้ลงคอลัมน์ **ผล** ของ `tab:eval`
และลง `records/calibration.md` ในวันเดียวกัน ตัวเลขที่ได้มีดังนี้

- **slam:** ค่าคลาดเคลื่อนดิบที่แย่ที่สุด (worst raw), ค่าหลังชดเชยการหมุน (worst aligned) และค่าการวัดซ้ำ (repeatability)
- **object:** ค่าคลาดเคลื่อนเฉลี่ยและค่าที่แย่ที่สุด, การกระจายตัวระหว่างมุมมอง (across-pass spread) และจำนวนวัตถุซ้ำ (duplicates)
- **resource:** CPU, GPU, RAM สูงสุด และ tj สูงสุด ของแต่ละช่วงที่วัด

## สิ่งที่ต้องเขียนประกอบรูป

- **SLAM:** ให้รายงานทั้ง **ค่าดิบ** และ **ค่าหลังชดเชยการหมุนของแกน**
  การเล็งหุ่นยนต์ให้ขนานกับผนังด้วยตาคลาดได้ 3–4° ซึ่งที่ระยะ 5 ม. เท่ากับ 30 ซม.
  และความคลาดนี้ไม่ใช่ความผิดพลาดของ SLAM (วิธีนี้เหมือนการคำนวณ ATE มาตรฐาน)
  ข้อมูลวันที่ 22 ก.ย. มีค่าดิบ 29.8 ซม. และค่าหลังชดเชย 10.4 ซม. จากรอบเดียว 4 จุด
  ค่าที่วัดได้เป็น **ขอบบน** ของความคลาดเคลื่อน เพราะรวมความคลาดเคลื่อนจากตลับเมตรและการจอดไว้ด้วย
- **วัตถุ:** ค่าที่ได้ต้องมาจาก **หลายมุมมอง** ตามถ้อยคำของเกณฑ์ ค่า 0.08 ม. ในรายงานปัจจุบันมาจากมุมเดียว
- **ทรัพยากร:** ถ้ามีคอร์เดียวสูงเกือบ 100 % แต่ค่าเฉลี่ยผ่านเกณฑ์ ให้รายงานค่าเฉลี่ย
  และระบุว่า executor แบบเธรดเดียวคือเพดานจริงของระบบ
  ค่าจากรอบวันที่ 22 ก.ย. คือ CPU เฉลี่ย 48.2 % และสูงสุด 97.7 % ในช่วง 894 วินาที
  แต่รอบนั้นไม่มีข้อมูลรายจุด จึงต้องวัดใหม่เพื่อวาดกราฟ
